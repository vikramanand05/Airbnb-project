# Power BI and Tableau build guide

The repository exports equivalent CSV and Parquet tables. Power BI can import either format; Tableau can use the CSV files or Parquet where supported. A native `.pbix` or `.twb` is not generated by the Python toolchain.

## Files to import

- `data/processed/listings.csv` or `listings.parquet`
- `data/processed/review_events.csv` or `review_events.parquet`
- `data/processed/market_summary.csv`
- `data/processed/country_coverage.csv`
- `data/processed/missingness.csv`
- `data/processed/availability_summary.csv`
- `data/processed/data_dictionary.csv`

Prefer Parquet for the two large fact tables because it preserves types and loads faster. Use CSV when portability is more important.

## Power BI build steps

1. Open Power BI Desktop and choose **Get data**.
2. Import `listings.parquet` and `review_events.parquet`.
3. In Power Query, confirm that IDs are text, dates are dates, flags are Boolean, and numeric fields are decimal or whole numbers as appropriate.
4. In Model view, create `listings[listing_id]` (one) to `review_events[listing_id]` (many), single-direction.
5. Create the measures below in a dedicated measure table.
6. Add report-level slicers for Market, Government Area, Room Type, Property Type, Rating, and the relevant availability horizon.
7. Configure the price page so a single market must be selected. Do not add country or global price rankings.
8. Add the limitation text shown below to every price, availability, and review page.
9. Refresh after rerunning `airbnb-analysis all`; the exported schemas stay stable.

### Recommended DAX measures

```DAX
Listings = DISTINCTCOUNT(listings[listing_id])

Rated Listings =
CALCULATE(
    [Listings],
    NOT ISBLANK(listings[review_score_rating])
)

Median Rating = MEDIAN(listings[review_score_rating])

Median Price - One Market =
IF(
    HASONEVALUE(listings[market]),
    MEDIANX(
        FILTER(listings, listings[price] > 0),
        listings[price]
    ),
    BLANK()
)

Price Context Message =
IF(
    HASONEVALUE(listings[market]),
    "Source price units - within selected market",
    "Select exactly one market for price analysis"
)

Extreme Price Listings =
CALCULATE([Listings], listings[price_extreme] = TRUE())

Median Available Days 365 = MEDIAN(listings[availability_365])

Review Events = COUNTROWS(review_events)
```

Do not create an occupancy measure from availability.

## Tableau build steps

1. Connect to the two Parquet or CSV files.
2. Relate `listings` to `review_events` on `listing_id`, one-to-many.
3. Assign geographic roles to Country and Country Code. Use Longitude and Latitude directly for listing points.
4. Add Market, Government Area, Room Type, Property Type, and Rating filters.
5. Set the Market filter to single-value mode on the price dashboard.
6. Create the guarded price calculation:

```text
IF COUNTD([Market]) = 1 THEN
    MEDIAN(IF [Price] > 0 THEN [Price] END)
END
```

7. Keep price, availability, and review caveats visible rather than hidden in tooltips.

## Recommended report layout

### Page 1: Overview

- Cards: Listings, Markets, Countries, Median Rating.
- Horizontal bars: listing counts by market and property type.
- Map: listing points colored by room type when multiple markets are selected.
- Slicers: Market, Government Area, Room Type, Property Type, Rating.

### Page 2: Prices

- Required single-value Market slicer.
- Cards: listing count, median source price units, first and third quartiles, flagged extreme count.
- Histogram or box plot by room type.
- Neighborhood dot plot: median price on x-axis, government area on y-axis, listing count as size.
- Detail table with price quality flags.

Visible note: `The source has no currency field. Values are source price units and may be compared only within the selected market.`

### Page 3: Availability

- Horizon selector for 30, 60, 90, and 365 days.
- Box plots by room type.
- Cards: listing count, median available days, interquartile range.

Visible note: `Availability is a forward-looking snapshot, not reservations, occupancy, bookings, demand, or revenue.`

### Page 4: Review activity

- Monthly review-event line chart.
- Cards: event count, earliest review date, latest review date.
- Optional small multiples by market, using event counts only.

Visible note: `Review activity is an incomplete and biased proxy. It is not a count of stays or a measure of true seasonality.`

### Page 5: Data quality

- Cards: source rows, duplicate IDs, invalid coordinates, missing prices, extreme prices.
- Missingness bar chart.
- Data dictionary table.
- Methodology and limitation text.

## Visual and interaction rules

- Use one accent color for selected data and neutral grays for context.
- Show sample size in each chart subtitle or tooltip.
- Keep outliers visible; use `price_extreme` as a legend or filter.
- Use median and quartiles for price. Do not rely on means alone.
- Disable or blank price KPIs when more than one market is in context.
- Use `last_scraped` for a data-freshness label.

## Validation checklist

- Listing count equals the row count in `listings` and the distinct listing ID count.
- Review Events equals the row count in `review_events`.
- The relationship does not duplicate listing-level measures.
- Price cards go blank when multiple markets are selected.
- Map longitude and latitude are not reversed.
- No visual or tooltip uses the words occupancy, bookings, demand, revenue, or seasonality as a conclusion from availability.
- Review charts say **review-activity proxy**.
